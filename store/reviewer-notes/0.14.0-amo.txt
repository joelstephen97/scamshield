0.14.0 adds no permission, no host and no network request; nothing is sent anywhere. It is a user-experience release: (1) in-page warnings now remember the user's decisions locally: a per-site, per-warning-type mute ("Don't warn me on this site", stored in browser.storage.local under the existing settings object and reversible in Settings), a one-day pause when the warning bar is closed, and a one-hour pause when "Continue anyway" is chosen on the full-page warning; these reuse the pause/allowlist mechanism and the declarativeNetRequest allow rules already present since 0.12.0, and every such control only accepts a trusted user gesture (event.isTrusted) on the extension's own UI; (2) a copy of a terminal command or crypto address triggered by the user's own click on a site's copy button is shown as an informational notice and no longer counted as a blocked threat (the ClickFix fake-CAPTCHA detection is unchanged); (3) a false-positive fix so a page posting to its own subdomain is not reported as a third-party leak; (4) the warning bar, full-page warning, notices and dialogs are redesigned (same content-script injection, same single purpose). No remote code, no WebAssembly; all detection is unminified vanilla JS bundled in the package. web-ext lint: 0 errors; the 8 warnings are the pre-existing UNSAFE_VAR_ASSIGNMENT notes on innerHTML writes of constant SVG icon strings. Data collection permissions unchanged: required none, optional websiteActivity for the off-by-default community reporting. Source: https://github.com/joelstephen97/scamshield (tag v0.14.0).
